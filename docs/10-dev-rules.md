# 10. Правила разработки для Claude

Из PRD, часть 6. Дублируются в корневом `CLAUDE.md`.

1. Не делать весь проект одним большим действием.
2. Сначала структура страниц и дизайн.
3. Затем Supabase и база данных.
4. Потом основные функции маркетплейса.
5. AI-функции подключать по одной.
6. После каждого этапа проверять, что сайт работает.
7. В готовых функциях не подменять реальные данные из БД фиктивными.
8. Не создавать кнопки, которые ничего не делают.
9. Не класть секретные API-ключи во фронтенд.
10. Не ломать существующие рабочие функции при добавлении новых.
11. TypeScript и понятная структура компонентов.
12. Если нужен API-ключ или внешняя интеграция, сказать об этом и объяснить, как подключить.
13. Нереализованную функцию честно помечать как недоступную, а не имитировать.
14. Не выдумывать результаты анализа и не гарантировать безопасность по фото.
15. Перед изменением схемы БД объяснять, какие таблицы и связи меняются.

**Главный приоритет:** работающий MVP (регистрация, объявления, каталог, БД, AI работают по-настоящему), а не красивый макет.

## Контекст команды
- 4 студента, опыта программирования почти нет.
- Claude пишет код сам и объясняет, что команда должна сделать руками в Lovable и Supabase (создать проект, вставить ключ в Secrets, нажать кнопку и т. п.).
- Объяснения — простым языком, по шагам.

## Рекомендации из PRD
- Не начинать с пяти AI-функций: сначала рабочий маркетплейс.
- Первым AI-модулем удобно взять Project Reuse Planner.
- Reuse Planner берёт объявления только из Supabase.
- Не обещать техническую экспертизу по фото (прочность кирпича, металла, древесины).
