## ⚠️ Контекст: студенческий демо-проект

Это учебный проект, а не продукт для продакшена. **Цель — сайт, который можно показать на защите или демо.** Полнота и масштабируемость не нужны.

Что из этого следует:
- Из PRD делаем только то, что видно в демо-сценариях ([06-user-flows.md](06-user-flows.md)).
- Везде выбираем самое простое решение, которое работает: без админки, жалоб, лимитов, i18n-инфраструктуры и сложных RLS-схем.
- Тестовые объявления и фото заранее загружаем в базу (seed). Это нормально.
- AI-функции должны **реально** вызывать модель на демо, но можно упрощать: одна Edge Function, минимальная проверка ответа.
- Пункты PRD «на будущее» и «безопасность продакшена» — это ориентир, а не обязательство.

Итоговые решения по объёму — в [open-questions.md](open-questions.md) и [09-roadmap.md](09-roadmap.md).

## Коротко о продукте

**QaitaBuild** — веб-маркетплейс для Казахстана, где продают, покупают и повторно используют строительные материалы. От обычной доски объявлений его отличают пять AI-инструментов: они анализируют фото материалов, подбирают вторичные материалы под проект, советуют, как восстановить материал, ищут, что сохранить перед демонтажем, и формируют цифровой паспорт материала.

- **Стек:** React + TypeScript + Tailwind + shadcn/ui (Lovable), Supabase (Postgres, Auth, Storage, Edge Functions), мультимодальная AI-модель через API.
- **Команда:** 4 студента, опыта программирования почти нет. Разработка идёт поэтапно через Claude и Lovable.
- **Главный приоритет:** работающий MVP, а не красивый макет.
