# 3. Пять AI-функций

ИИ — главное отличие QaitaBuild от обычных досок объявлений.

## Общие принципы

- Все пять функций могут работать на **одной мультимодальной модели** через API, но у каждой свой системный промпт и сценарий.
- Модель отвечает **структурированным JSON**, интерфейс показывает его карточками.
- Вызовы идут **только с сервера** (Supabase Edge Functions); ключи лежат в Supabase Secrets.
- Каждый анализ сохраняется в `ai_analyses` (история в кабинете).
- Если AI-сервис недоступен, пользователь видит понятное сообщение об ошибке, а не выдуманный результат.

## Жёсткие ограничения (для всех функций)

1. ИИ **не утверждает**, что материал прочный, безопасный или годится для несущих конструкций, только по фото.
2. ИИ **не выдумывает** наличие материалов, цены и характеристики.
3. ИИ **не даёт опасных рекомендаций** использовать повреждённые материалы в ответственных конструкциях.
4. ИИ **не выдаёт за факт** скрытые коммуникации, прочность и безопасность конструкций.
5. Результат — это **предварительный визуальный анализ**, он не заменяет специалиста и лабораторную проверку.
6. Если функция ещё не реализована, она честно помечена как недоступная, без имитации.

## AI-1. Material Inspector

**Назначение:** анализ стройматериала по фото.
**Вход:** 1+ фото материала (опционально название и категория от пользователя).

ИИ должен:
- предположить тип материала;
- найти видимые дефекты и повреждения;
- описать визуальное состояние;
- дать предварительную оценку пригодности для дальнейшего использования;
- указать, какую информацию нужно уточнить у пользователя.

**Пример** (б/у кирпич): керамический кирпич; есть загрязнения и небольшие сколы; нужно проверить наличие трещин; предварительно подходит для некоторых ненесущих конструкций и ландшафтных работ после проверки специалистом.

**Выход:** структурированная карточка. Используется при создании объявления и как основа паспорта (AI-5).

## AI-2. Project Reuse Planner ⭐ (ключевая функция)

**Назначение:** подобрать вторичные материалы под проект пользователя.
**Вход:** описание проекта обычным текстом.

> «Хочу отремонтировать ванную 6 м². Нужны плитка, раковина и материалы для отделки стен. Хочу по максимуму использовать б/у материалы».

ИИ должен:
1. проанализировать описание;
2. выделить нужные материалы;
3. оценить характеристики и количество;
4. предложить, какие новые материалы заменить вторичными;
5. объяснить выбор.

Система затем:
6. **ищет реальные объявления в Supabase** (по категориям и ключевым словам, которые выделил ИИ);
7. показывает найденные объявления.

| Нужный материал | Возможная альтернатива |
|---|---|
| Новая керамическая плитка | Б/у плитка в хорошем состоянии |
| Новая раковина | Восстановленная раковина |
| Деревянные декоративные элементы | Древесина для повторного использования |

**Критично:** показываются только объявления, которые действительно есть в базе. Если подходящих нет, система честно об этом говорит. ИИ подбирает **типы** альтернатив, а **сами объявления** берутся из БД.

**[предложение]** Архитектура: Edge Function → ИИ возвращает `{ materials: [{ name, category, quantity, unit, reuse_alternative, reason, search_keywords[] }] }` → по каждому материалу SQL-запрос к `listings` (category + `ilike` по keywords, `status = 'active'`) → ответ клиенту: план и найденные объявления. Результат сохраняется в `project_requests`.

## AI-3. Recovery Planner

**Назначение:** рекомендации по восстановлению и повторному использованию.
**Вход:** фото или уже существующее объявление.

ИИ должен:
- определить видимые проблемы;
- предложить способы очистки;
- предложить способы восстановления;
- объяснить, для чего можно повторно использовать материал;
- указать, какие дополнительные проверки нужны;
- предупредить, когда восстанавливать нецелесообразно.

**Пример** (старая доска): очистить; снять старое покрытие; проверить на гниль и жучков; после проверки рассмотреть для декора или мебели.

## AI-4. Pre-Demolition Scanner

**Назначение:** предварительно найти, что сохранить перед демонтажем.
**Вход:** фото комнаты, здания или помещения.

ИИ должен:
- найти видимые строительные элементы;
- составить список того, что потенциально можно сохранить;
- предложить варианты повторного использования;
- объяснить, почему стоит сохранить каждый элемент.

**Пример** (старая кухня): дверцы шкафов из дерева, металлические элементы, раковина, плитка, дверная конструкция.
Обязательная оговорка: *«Возможно, эти элементы можно сохранить и использовать повторно. Перед демонтажем проверьте их фактическое состояние и возможность безопасного снятия»*.

Пользователь отмечает нужные элементы → может перейти к созданию объявлений (форма предзаполнена **[предложение]**).

## AI-5. Material Passport

**Назначение:** цифровой паспорт стройматериала.
**Создаётся:** после AI-анализа, привязан к объявлению.

Содержит: название, категорию, фото, предполагаемые характеристики, визуальное состояние, дефекты, рекомендации по восстановлению, варианты повторного использования, дату создания, статус подтверждения.

**Три источника данных, которые нужно визуально различать:**
1. 🧑 указано пользователем;
2. 🤖 предположение ИИ;
3. ✅ подтверждено пользователем или специалистом.

Продавец может дополнить и исправить паспорт перед публикацией.
Паспорт **не является** официальным сертификатом качества или безопасности. Дисклеймер виден в интерфейсе **[предложение]**.

## Порядок реализации AI

По этапу 4 в PRD: Inspector → Recovery → Passport → Reuse Planner → Pre-Demolition.
Отдельная рекомендация в том же документе: **начать AI с Reuse Planner**, потому что он лучше всего показывает пользу продукта. Противоречие вынесено в [open-questions.md](open-questions.md).
