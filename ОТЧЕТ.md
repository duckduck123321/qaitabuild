# Отчёт по проекту QaitaBuild

**QaitaBuild** — маркетплейс строительных материалов для повторного использования (Казахстан) с AI-инструментами.

| | |
|---|---|
| Сайт | https://qaitabuild.vercel.app |
| Исходный код (GitHub) | _ссылка будет добавлена после создания репозитория_ |
| Стек | React + TypeScript + Tailwind (Vite), Supabase (Postgres, Auth, Storage, Edge Functions), Vercel |

## 1. Какая AI-модель используется

**Google Gemini** (Gemini API от Google), мультимодальная модель: понимает и текст, и фото, отвечает в формате JSON.

- Основная модель: **`gemini-3.5-flash-lite`**.
- Если она недоступна или упёрлась в лимит, функция по очереди пробует запасные: `gemini-3.1-flash-lite`, затем `gemini-flash-latest`.
- Список моделей можно поменять без правки кода, через секрет `GEMINI_MODEL` в Supabase.
- Параметры запроса: `temperature: 0.4`, `responseMimeType: application/json` и строгая JSON-схема ответа (`responseSchema`) для каждого инструмента.

### Как AI подключён к сайту

```
Браузер (сайт)  →  Supabase Edge Function «ai»  →  Gemini API
                   ключ GEMINI_API_KEY хранится
                   в Supabase Secrets
```

- Сайт не обращается к Gemini напрямую. Он вызывает серверную функцию Supabase ([supabase/functions/ai/index.ts](supabase/functions/ai/index.ts)), и уже она отправляет запрос в Gemini.
- API-ключ хранится только в Supabase Secrets. Ни в коде сайта, ни в репозитории его нет.
- Код вызова на стороне сайта: [src/lib/ai.ts](src/lib/ai.ts).
- Результаты анализов вошедших пользователей сохраняются в таблицу `ai_analyses` (история в личном кабинете).

## 2. AI-функции сайта

| Функция | Что получает | Что делает |
|---|---|---|
| **Project Reuse Planner** | Текстовое описание проекта | Составляет список нужных материалов, предлагает б/у альтернативы и **ищет реальные объявления в базе сайта** |
| **Material Inspector** | Фото материала | Определяет тип, категорию, состояние и дефекты, предлагает название объявления |
| **Material Passport** | Ответ Inspector | Сохраняет результат анализа как «цифровой паспорт» на странице объявления (статус «предположение ИИ» или «подтверждено продавцом») |
| **Recovery Planner** | Фото материала | Составляет план очистки и восстановления, перечисляет нужные проверки и случаи, когда восстанавливать не стоит |
| **Pre-Demolition Scanner** | Фото помещения | Находит элементы, которые можно снять и продать или использовать повторно |

## 3. Основные промты

Промты лежат в файле [supabase/functions/ai/index.ts](supabase/functions/ai/index.ts). Они передаются модели как системная инструкция (`systemInstruction`). Каждый промт состоит из общих правил и задания для конкретного инструмента.

### 3.1. Общие правила (входят в каждый промт)

```
Ты — помощник маркетплейса QaitaBuild (Казахстан), где продают и покупают строительные материалы б/у и остатки после ремонта.
Отвечай только на русском языке, коротко и по делу.
Строгие правила:
- Ты делаешь только предварительный визуальный анализ. Никогда не утверждай, что материал прочный, безопасный или годится для несущих конструкций.
- Не придумывай цены, наличие товаров, марки и точные характеристики, которых не видно.
- Не советуй использовать повреждённые материалы в ответственных конструкциях. Если нужна проверка — так и скажи.
- Категории материалов: bricks_blocks — кирпич и блоки; wood_lumber — древесина и пиломатериалы; metal — металл; tiles — плитка и керамогранит; doors_windows — двери и окна; plumbing — сантехника; electrical — электрика; roofing — кровельные материалы; finishing — отделочные материалы (ламинат, гипсокартон, краска, обои); other — другое.
```

### 3.2. Project Reuse Planner

```
Пользователь описывает свой строительный проект или ремонт. Задача:
1) выдели 3–7 материалов, которые понадобятся;
2) для каждого оцени примерное количество (если можно понять из описания, иначе "уточнить");
3) предложи, чем его можно заменить из б/у или остатков, и объясни почему;
4) дай 2–4 ключевых слова для поиска объявлений — короткие существительные в именительном падеже, как продавец назвал бы материал в объявлении (например: "плитка", "керамогранит", "раковина", "доска", "кирпич").
Если какой-то материал по соображениям безопасности лучше покупать новым (например, для несущих конструкций или газа), укажи это в reason.
```

Формат ответа: `summary`, список `materials` (название, категория, количество, б/у альтернатива, причина, ключевые слова), `tips`.
Поиск объявлений выполняет не модель, а сайт: по ключевым словам из ответа он ищет реальные объявления в базе. Поэтому ИИ не может «выдумать» товар, которого нет.

### 3.3. Material Inspector (и Material Passport)

```
Пользователь прислал фото строительного материала, который хочет продать или использовать повторно.
Опиши, что видно на фото: предполагаемый тип материала, видимые дефекты, визуальное состояние, как его можно восстановить и где применить повторно.
Предложи короткое название для объявления (до 60 символов).
Если на фото не строительный материал — поставь is_construction_material = false и кратко объясни в visual_condition.
Укажи, что ещё нужно уточнить у продавца (размеры, количество, наличие трещин и т. п.).
```

Формат ответа: тип материала, название, категория, состояние, уверенность (low / medium / high), дефекты, рекомендации по восстановлению и повторному использованию, вопросы продавцу. Из этого ответа собирается Material Passport.

### 3.4. Recovery Planner

```
Пользователь прислал фото материала и хочет понять, можно ли его восстановить и использовать снова.
Опиши видимые проблемы, способы очистки и восстановления, варианты повторного применения, какие проверки нужны перед использованием и в каких случаях восстанавливать нецелесообразно.
```

### 3.5. Pre-Demolition Scanner

```
Пользователь прислал фото помещения перед ремонтом или демонтажем.
Найди видимые строительные элементы, которые потенциально можно аккуратно снять и использовать повторно или продать (двери, окна, плитка, сантехника, радиаторы, паркет, кирпич, металл, фасады мебели и т. п.).
Для каждого объясни, зачем его сохранить, где применить и на что обратить внимание при снятии.
Не делай выводов о скрытых коммуникациях, прочности и безопасности конструкций.
```

## 4. Ограничения и безопасность AI

- Ответ модели всегда проверяется по JSON-схеме, поэтому сайт получает предсказуемую структуру.
- Модель не гарантирует прочность и безопасность по фото. Это прописано в промте, а на страницах есть предупреждение.
- Цифровой паспорт помечается как «предположение ИИ», пока продавец сам не подтвердит данные.
- Ограничения на входные данные: текст от 10 до 2000 символов, фото только JPG, PNG или WebP.
- API-ключ хранится только на сервере (Supabase Secrets).

## 5. Как запустить проект

```bash
npm install
npm run dev
```

Без файла `.env.local` сайт работает в демо-режиме (данные в браузере, AI отключён). Чтобы подключить Supabase и AI, скопируйте `.env.example` в `.env.local` и заполните его. Подробные шаги — в [README.md](README.md).
